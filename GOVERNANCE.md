# Governance

CesiumJS COPC Runtime currently uses a maintainer-led model. Maintainers are
responsible for roadmap decisions, review, releases, security response, and community
standards. Decisions should be recorded in issues, pull requests, or architecture
decision records so that project history remains inspectable.

## Decision process

- Small, reversible changes are decided through pull-request review.
- Public API and architecture changes start with an issue and document alternatives.
- Security reports follow [SECURITY.md](SECURITY.md).
- Releases require passing CI, an updated changelog, and package dry-run verification.

As regular contributors emerge, maintainership can be expanded based on sustained,
constructive contributions rather than a fixed contribution count.
